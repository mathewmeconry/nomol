# Nomol

Self-service video replay for Swiss Geräteturnen training. A tablet at the apparatus records a
gymnast when they give the start sign in the start zone (or tap the record button), follows them
through the routine, and shows the clip right after they land. Runs as an installable web app (PWA).

**Live:** https://mathewmeconry.github.io/nomol/ (deployed from `main`)

## Requirements

- Node >= 24 (`nvm use`)
- pnpm (`corepack enable`)

## Getting started

```bash
pnpm install
pnpm dev
```

The app runs on `http://localhost:5173` (`pnpm dev --port 5180` if that port is taken).

Camera access needs a secure context: `localhost` works, a tablet on the network needs HTTPS.
Pose detection loads its WASM and model from the internet. After one visit with internet, a
service worker (`apps/web/public/sw.js`, production builds only) keeps the app and the model available
offline.

Live detection (start sign, following, stopping) uses MediaPipe Pose. The replay skeleton is
computed after each recording with the same model, each frame turned so the gymnast appears
upright, which handles handstands far better.

Clips are kept in the browser (IndexedDB) until deleted, so they survive reloads. Nothing is
uploaded; **Export** in the player shares or downloads a clip as video plus `.nomol.txt` (JSON body
points per frame, start zone, aspect ratio).

## Setting up a tablet

1. Mount the tablet so the camera sees the whole apparatus, including the floor in front of it.
2. Open the app and allow camera access. Install it to the home screen for full-screen mode.
3. Tap **Startzone** and drag the area where gymnasts stand before they start. Its bottom edge
   must sit on the floor where the feet are: anything not standing on both feet counts as an
   element. Recordings stop ~6 s after the last element (or when the gymnast leaves the picture),
   and the replay loops just the routine.
4. For apparatus like Sprung, pick **Auto von links/rechts** (the side the run-up comes from) and
   draw the start zone over the apparatus and the landing. Each run-in starts a recording by
   itself, including the 1.5–3 s before it was recognised. **Auto bei Tempo** starts on anyone
   faster than walking in any direction, e.g. swinging on the rings or running up on the floor.
5. Detection looks only at the start zone and around it (and wherever the recorded gymnast
   goes), which finds people far from the camera. Draw the zone over everything a gymnast
   should be found in before the start.

## Layout

A pnpm workspace:

- `apps/web`: the web app (`@nomol/web`)
- `apps/native`: the Android app (`@nomol/native`, Expo / React Native), being ported from the
  web app. It detects the start and end of a routine, records it (an automatic start including
  the seconds before it), keeps the clips on the phone, computes the replay skeleton and
  replays and exports them.
- `packages/core`: pure logic shared by both apps (`@nomol/core`): start and stop detection,
  start zone, clips, export format, pre-roll, replay skeleton rotation, settings
- `packages/native-modules`: the Android app's native code (`@nomol/native-modules`, Kotlin
  Nitro modules): MediaPipe pose detection on camera frames and on the replay skeleton's
  stills, the video recorder with its look-back buffer, the start beep and sharing several
  files at once

## Android app

Built locally, no Expo cloud services. Needs JDK 21 and an Android SDK with build-tools 37.0.0,
platform android-37 and NDK 30.0.16248370 (paths default to `/usr/lib/jvm/java-21-openjdk` and
`/opt/android-sdk`; override with `JAVA_HOME` / `ANDROID_HOME`), and CMake in `/usr/bin`.

```bash
pnpm android:build     # expo prebuild + Gradle release build (arm64), takes a few minutes
pnpm android:install   # adb install of apps/native/android/app/build/outputs/apk/release/app-release.apk
```

The release APK is signed with the debug key and installs directly on a phone with USB debugging.
`apps/native/android/` is generated by `expo prebuild` and not committed. The first build
downloads MediaPipe's pose models (~36 MB) and bundles them, so the app needs no internet.

## Scripts

Run from the root; they cover the whole workspace.

- `pnpm dev`: dev server with HMR
- `pnpm build` / `pnpm preview`: static production build in `apps/web/build/client`, and a
  server for it
- `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test:ci`: the checks CI runs
- `pnpm knip`: find unused files, exports and dependencies

## Deployment

The app is a static single-page app: camera, pose detection and recording all run in the
browser. Every push to `main` runs the checks and deploys `apps/web/build/client` to GitHub Pages
(`.github/workflows/deploy.yml`). Pages serves it under `/nomol/`, set at build time with
`BASE_PATH=/nomol/`.

Any static host works too, e.g. with Docker (nginx):

```bash
docker build -t nomol .
docker run -p 8080:80 nomol
```
